# Страницы приложения

## RBAC

Иерархия: `USER <- MODER <- ADMIN` (старшая наследует права младшей).
Доступ `USER` означает `USER, MODER, ADMIN`; `MODER` означает `MODER, ADMIN`.

Маршрут — путь к FXML для `Navigator.goTo(...)`.

| №   | Название страницы                            | Маршрут (FXML)                                             | Доступ            | Назначение                                                                                                      |
| --- | -------------------------------------------- | ---------------------------------------------------------- | ----------------- | --------------------------------------------------------------------------------------------------------------- |
| 1   | Вход (email + пароль)                        | `/fxml/LoginForm.fxml`                                     | гость (публичная) | Аутентификация через `AuthService`, после успеха → №2                                                           |
| 2   | Список ресурсов и сортировка (главная)       | `/fxml/ResourceList.fxml` (переименовать из `Search.fxml`) | `USER`            | Поиск/фильтр/сортировка, пагинация `offset/count` через `ResourceService.search`                                |
| 3   | Просмотр метаданных документа                | `/fxml/ResourceDetails.fxml` (новая)                       | `USER`            | Только чтение: `ResourceService.getById` → `title, description, createdAt, updatedAt, uuid`                     |
| 4   | Форма ресурса (создание/редактирование)      | `/fxml/ResourceForm.fxml` (новая)                          | `MODER`           | `create/update` через `ResourceService`; удаление — действием из №2/№3 с подтверждением, без отдельной страницы |
| 5   | Список пользователей                         | `/fxml/UserList.fxml` (новая)                              | `ADMIN`           | Поиск/фильтр через `UsersService.search` + `UserFilter`; удаление действием из списка                           |
| 6   | Форма пользователя (создание/редактирование) | `/fxml/UserForm.fxml` (новая)                              | `ADMIN`           | `create` через `RegisterData`, `update` через `UpdateUserData`, `getById` для предзаполнения                    |

## Примечания по реализации

* №1: упростить `LoginFormController` — удалить `firstName/lastName/thirdName`, оставить `email + password` + вызов `AuthService`/`LoginRequest` (сейчас там заглушка `authenticate()` с `Role.USER`).
* №2: переименование `Search.fxml → ResourceList.fxml` + переименование `SearchController → ResourceListController`; обновить `Program.INITIAL_PAGE_PATH` и `navigator.goTo("/fxml/Search.fxml")` в `LoginFormController`.
* SoC: списки (№2, №5) не содержат логики форм; формы (№4, №6) работают в двух режимах `create/edit` по наличию `uuid`, валидация через существующие `validation/*Validator`.
* Кнопки create/edit/delete рендерятся по роли из `Session.getCurrentUser().role`, а не отдельными страницами.
