# Страницы приложения

## RBAC

Иерархия: `USER <- MODER <- ADMIN` (старшая наследует права младшей).
Доступ `USER` означает `USER, MODER, ADMIN`; `MODER` означает `MODER, ADMIN`.

Маршрут — путь к FXML для `Navigator.goTo(...)`.

## Паттерн взаимодействия с API

UI не ходит в HTTP напрямую. Контроллер вызывает сервис («middleware»):
`Controller → services.getXService() → ApiClient → HTTP + Session (Bearer)`.
Сервис кладёт пользователя/токены в `Session`, ошибки пробрасывает как
`ServiceException`, контроллер показывает их через `Alert`.
Пример: docs/examples/how-to-interact-with-api-from-ui-via-middleware.md.

| --- | -------------------------------------------- | ------------------------------------ | ----------------- | --------------------------------------------------------------------------------------------------------------- | ------------- |
| 1   | Вход (email + пароль)                        | `/fxml/LoginForm.fxml`               | гость (публичная) | Аутентификация через `AuthService`, после успеха → №2                                                           | @vladcheck     |
| 2   | Список ресурсов и сортировка (главная)       | `/fxml/ResourceList.fxml`            | `USER`            | Поиск/фильтр/сортировка, пагинация `offset/count` через `ResourceService.search`                                | @miyagi18      |

## Интеграции страниц с эндпоинтами (через сервисы)

Базовый URL: `api.baseUrl` (`http://localhost:8080`).

| №   | Действие UI                             | Сервис (middleware)                                  | ApiClient → HTTP                                                                                                                       |
| --- | --------------------------------------- | ---------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------- |
| 1   | Войти                                   | `AuthService.login(email, password)`                 | `POST /api/v1/auth/login` (`LoginRequest`), затем `GET /api/v1/user/me`; токены → `Session`                                            |
| 1   | Выйти                                   | `AuthService.logout()`                               | `POST /api/v1/auth/logout` (`RefreshTokenRequest`), затем `Session.clear()`                                                            |
| 2   | Поиск/фильтр/сортировка ресурсов        | `ResourceService.search(filter, offset, count)`      | `GET /api/v1/resource?title=&description=&offset=&count=&sortBy=createdAt&sortDir=desc`                                                |
| 3   | Открыть метаданные                      | `ResourceService.getById(id)`                        | `GET /api/v1/resource/{id}`                                                                                                            |
| 3   | Список/скачать/загрузить/удалить файлы  | `FileService.{uploadFile, downloadFile, deleteFile}` | `POST /api/v1/resource/{id}/file` (multipart), `GET /api/v1/resource/{id}/file/{fileId}`, `DELETE /api/v1/resource/{id}/file/{fileId}` |
| 3   | Экспорт файлов ресурса                  | `ExportService.exportResourceFiles(id, dir)`         | `GET /api/v1/admin/resource/{id}/files/export` (бинарный ответ → файл)                                                                 |
| 4   | Создать ресурс                          | `ResourceService.create(title, description)`         | `POST /api/v1/resource` (`CreateResourceRequest`)                                                                                      |
| 4   | Обновить ресурс                         | `ResourceService.update(id, title, description)`     | `PUT /api/v1/resource/{id}` (`UpdateResourceRequest`)                                                                                  |
| 4   | Удалить ресурс (из №2/№3)               | `ResourceService.delete(id)`                         | `DELETE /api/v1/resource/{id}`                                                                                                         |
| 5   | Поиск/фильтр пользователей              | `UsersService.search(filter, offset, count)`         | `GET /api/v1/admin?email=&firstName=&lastName=&role=&enabled=&offset=&count=&sortBy=createdAt&sortDir=desc`                            |
| 5   | Удалить пользователя (из списка)        | `UsersService.delete(id)`                            | `DELETE /api/v1/admin/{id}`                                                                                                            |
| 5   | Экспорт пользователей/ресурсов          | `ExportService.{exportUsers, exportResources}`       | `GET /api/v1/admin/users/export`, `GET /api/v1/admin/resource/export`                                                                  |
| 6   | Создать пользователя                    | `UsersService.create(RegisterData)`                  | `POST /api/v1/admin` (`RegisterRequest`: email, password, role, firstName, lastName)                                                   |
| 6   | Открыть пользователя для редактирования | `UsersService.getById(id)`                           | `GET /api/v1/admin/{id}`                                                                                                               |
| 6   | Обновить пользователя                   | `UsersService.update(id, UpdateUserData)`            | `PUT /api/v1/admin/{id}` (`UpdateUserRequest`: email, enabled, role, firstName, lastName)                                              |

Примечания:
* `ApiClient` при 401 (кроме `/api/v1/auth/*`) один раз обновляет токены через
  `POST /api/v1/auth/refresh` и повторяет запрос; если refresh нет/не удался —
  исходный ответ уходит в `ServiceException`.
* Клиентская валидация (FormsFX + `validation/*Validator`) срабатывает до вызова
  сервиса; серверные ошибки (`ApiException` → `ServiceException`) показывает контроллер.

## Примечания по реализации

* №1: ✅ готово — `LoginFormController` только email + пароль, вызов `AuthService`.
* №2: ✅ переименование `Search.fxml → ResourceList.fxml` готово; наполнить список:
  `ResourceService.search` + пагинация, фильтры `ResourceFilter(title, description)`.
* №3: ✅ готово — `ResourceDetailsController` (read-only): метаданные + таблица файлов
  со скачиванием (`FileService.downloadFile`), вход из №2 — `Navigator.goTo(path, c -> ...)`
  с `setResourceId(uuid)` + `load()`.
* Роли: `AuthServiceImpl.hasRole` сравнивает по уровню (`USER=0 < MODER=1 < ADMIN=2`),
  поэтому `isModerator()` возвращает true и для `ADMIN` — соответствует RBAC выше.
* SoC: списки (№2, №5) не содержат логики форм; формы (№4, №6) работают в двух режимах `create/edit` по наличию `uuid`, валидация через существующие `validation/*Validator`.
* Кнопки create/edit/delete рендерятся по роли из `Session.getCurrentUser().role`, а не отдельными страницами.

## Интеграционные тесты (rough)

Стек: JUnit5 + AssertJ уже есть; TestFX headless настроен в `maven-surefire-plugin`
(`--enable-native-access=ALL-UNNAMED`). HTTP backend-а в тестах нет — ставим
стаб: WireMock (или подменный `ApiClient`) + TestFX для UI-слоя.

* IT-Auth (№1): мок `POST /api/v1/auth/login` → 200 с токенами + `GET /api/v1/user/me` → 200 `UserDto`;
  проверить: `Session` заполнен, переход на `ResourceList`; кейс 401 → `ServiceException`, показан `Alert`, перехода нет.
* IT-ResourceList (№2): мок `GET /api/v1/resource?...` → список `ResourceDto`;
  проверить: таблица/список отрисован, пагинация меняет `offset/count` в запросе;
  кейс 403 для `USER` без прав — сообщение об ошибке, без падения.
* IT-ResourceDetails (№3): мок `GET /api/v1/resource/{id}` → 200 и 404;
  проверить: поля метаданных показаны; 404 → `Alert` «не найден».
* IT-ResourceForm (№4): мок `POST /api/v1/resource` → 201 и `PUT /api/v1/resource/{id}` → 200;
  проверить: create/edit режимы по наличию `uuid`; `DELETE /api/v1/resource/{id}` после подтверждения.
* IT-UserList/UserForm (№5–6, ADMIN): мок `GET /api/v1/admin?...` → список,
  `POST /api/v1/admin` → 201, `PUT /api/v1/admin/{id}` → 200, `DELETE` → 204;
  проверить: фильтр `email/role/enabled` уходит в query params; создание требует все поля `RegisterData`.
* IT-Files/Export (№3/№5): мок multipart `POST .../file` → 201 `FileDto`,
  `GET .../file/{fileId}` → бинарник, `GET .../export` → бинарник;
  проверить: файл сохранён в `destinationDir`, имя взято из `Content-Disposition`.
* IT-Refresh: мок защищённого `GET` → 401, затем `POST /api/v1/auth/refresh` → 200,
  повторный `GET` → 200; проверить: запрос повторён с новым Bearer без участия UI.
